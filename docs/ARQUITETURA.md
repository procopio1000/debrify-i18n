## Authorities

    UI locale                  -> menus/controls/messages
    metadata language          -> titles/synopses/artwork
    audio preferred language   -> audio selection
    subtitle language          -> subtitle selection
    region                     -> availability/region

No authority implicitly writes another.

## Persisted state

    ui_locale_v1
      system
      en
      pt-BR
      ...

BCP 47 is the persisted representation.

V2 policy: App language is device-local.

It is not profile-scoped and is not synchronized through WebDAV.

## ShippingLocales

Generated locales and product-supported locales are separate concepts.

During migration an ARB may exist for testing without making the locale public.

MaterialApp resolution and the language selector use ShippingLocales.

CI verifies that ShippingLocales is a subset of the locales generated by AppLocalizations.

## Domain boundary

Models/services expose stable states, ids, reason codes and data.

They do not receive BuildContext and do not persist localized strings.

Presentation mappers convert stable states to AppLocalizations.

## Settings architecture

Settings metadata and copy must be separated.

Stable data:

- SettingsRowId
- icon
- destination/action
- capability
- URL where applicable

Localized data:

- title
- subtitle
- category
- search keywords

Settings Search rebuilds its localized index when locale changes.

## Semantic identity rule

Never use localized/display text for:

- equality/branching;
- persistence;
- protocol;
- analytics id;
- cache/database key;
- routing.

All sources is a confirmed example that must be migrated to stable id-based logic.

## Native platforms

### Android

values/strings.xml + values-pt-rBR/strings.xml, plurals when needed.

Flutter override is explicitly bridged to all native Activities that render UI.

### Apple

iOS/tvOS/macOS native strings, InfoPlist.strings and project-localization declarations are audited separately from Flutter ARB.

### Web

manifest/index metadata are part of the product shell and must not retain Flutter template placeholders.

### Windows/Linux

Native runner copy is inventoried and either localized or explicitly classified as brand/technical.

## Failure behavior

Locale corruption or localization failure must never block:

- app startup;
- profile recovery;
- backup restore;
- migration;
- playback recovery.

Fallback is always deterministic, with English available.
